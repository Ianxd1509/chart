## (a) song.ini — campos mínimos

Ubicación: en la raíz de la carpeta de la canción, junto a `notes.chart`.

**Obligatorios** (S5, "Mandatory Tags"): *"These tags are required for a song to appear in-game."*

```ini
[Song]
name = Titulo de la cancion
```
Cita S5: `[Song]` *«The first tag that must be at the top of the song.ini, do not edit it.»*; `name` *«The name of the song.»*

**Opcionales que escribimos** (S5 Optional Tags; S6 Standard Tags): `artist`, `album`, `genre`, `year`, `charter` (*«Author of the chart. An older frets tag can also be used instead of this one.»*). Para ChartForge: `name`, `artist`, `charter = ChartForge`. `album`/`genre`/`year` solo si la metadata externa los aportara (los dejan en blanco no lo hacemos: se omiten).

**Opcionales que NO escribimos, con razón citada:**
- `delay` — S5: *«Nowadays, it exists for legacy purposes. Using it is not recommended and might break the audio alignment.»* → **se omite** (alineación se logra con Offset=0 en el chart; ver (c)).
- `song_length` — S5: *«If the tag isn't present or is empty, it will be automatically generated by the game based on the audio file. Entering the value manually is not recommended.»* → se omite.
- `diff_guitar` / `diff_bass` / `diff_drums` — opcionales; el juego funciona sin ellos. Se escriben solo si Task 8 decide añadirlos (pueden quedar para Task 11 si la lista de canciones los pide).
- `lyrics`-flag: sugerido por detección automática (S6: *"This should be detected automatically by the game instead."*) → se omite.

## (b) Stems de audio y mute-miss

Nombres reservados (S4 `Supported-Audio-Files.md`, tabla copiada entera):
- `song` — *"Background audio not associated with any particular instrument, or the main audio stream if it is the only one present."* → nuestro stem **song.ogg**: lo que no es batería/bajo/guitarra/voz (demucs "other").

- `guitar` — *"Lead guitar audio, or the main audio stream if it is the only one present."* → **guitar.ogg**.
- `bass` — *"Bass guitar audio."* → **bass.ogg**.
- `drums` — *"Drums audio as a single stem. Should be ignored if numbered stems (drums_#) exist."* → **drums.ogg** (como no emitimos stems numerados, no lo ignora).
- `vocals vocals_1 vocals_2` — *"Vocals audio as a single stem…"* → **vocals.ogg**.
- `drums_1..4` — kick/snare/toms/cymbals por pieza; NO los usamos: demucs devuelve la batería como stem único. Si Task 11 encontrara que un solo `drums.ogg` no se silencia al fallar, el plan B documentado es escribir el mismo audio 4 veces como `drums_1.ogg..drums_4.ogg` (semántica del S4: cada número representa un instrumento del kit, y todas las piezas se silencian juntas en un miss de batería); decisión en Task 8/11.
- `crowd` — público; NO lo generamos (no hay stem demucs para él).
- `preview` — audio Master de 30 s del menú; NO lo generamos (opcional según S5/S6: CH genera vista previa del song file).

Formato `ogg` (S4 Recommended Formats: *«.ogg | Quality 8 (256 kbps) | Generally fine for single-file audio charts»*).

**Mute-miss**: el muting de CH actúa sobre el stem del instrumento que el jugador está fallando. Con un stem por instrumento (`drums.ogg`, `guitar.ogg`, `bass.ogg`), el resultado esperado al fallar es silenciar ese stem mientras song.ogg sigue sonando. ChartForge reparte los stems así:

| Instrumento del jugador | Stem que se escribe | Se silencia al fallar |
|---|---|---|
| Guitarra | `guitar.ogg` | sí |
| Bajo | `bass.ogg` | sí |
| Batería | `drums.ogg` | sí |
| Voz (no jugable en CH, S9) | `vocals.ogg` | no (sin gameplay) |

## (c) Sintaxis completa de notes.chart

Extensión y nombre: `notes.chart` (convención universal; el juego lo busca en la carpeta).

Codificación de líneas: Moonscraper escribe CRLF (S2 usa `Globals.LINE_ENDING`). ChartForge escribe **LF plano**: el parser de CH acepta ambos (su propio lector usa `Line.GetLineResult` tolerante: ver S3); el round-trip de tests usa el mismo formato que escribimos.

### Estructura general (S1 §"Header Tags and Data Sections")
> «To create a section, begin with a header tag contained within square brackets []. On a new line open a curly bracket {. Start writing the data on a new line. Close the section by placing a closed curly bracket } on a new line.»

> «Chart files always have a [Song] section, a [SyncTrack] section, and an [Events] section... The rest of the sections are used to define individual tracks»

### [Song] (S1 §[Song])
Formato de cada campo: *«[KEY] = [VALUE]»*.
- `Resolution = 192` — **obligatorio**: *«Resolution is the amount of ticks per quarter note of the entire chart... The standard values used are either 192 or 480.»* → ChartForge usa **192**.
- `Name`, `Artist`, `Album`, `Charter`, `Offset = 0` — Offset: *«It is HIGHLY recommended to ignore this parameter and leave this value at 0»* → **se escribe `Offset = 0`** (alineación).
- Streams de audio: *«Some games will not read these and instead choose to search for specifically-named audio files in the same directory as the chart file itself.»* → no los escribimos; los nombres (b) bastan.

### [SyncTrack] (S1 §B / §TS; S2 formatos)
- BPM — *«It has 1 value, a positive integer which is equal to the bpm rate * 1000. For example, 120 bpm will be stored as [0 = B 120000]»*:
  ```
  0 = B 120000
  ```
- Time Signature — *«The first value represents the numerator... The optional second parameter is stored as the logarithm of the denominator in base 2.»* (4/4 se escribe una sola de S2 si el denominador es 4):
  ```
  0 = TS 4
  ```

### [Events] (S1 §E; S2 `s_eventFormat`)
- Texto/sección/globales entre comillas: *«They always contain 1 value, and that value is always surrounded by quotes»*. Formato de Moonscraper (S2): `s_eventFormat = " = E \"{0}\""`.

- Secciones: *«The value is always prefixed with the string "section", followed by the title»*:
  ```
  112118 = E "section Solo 1"
  ```
- Letras: *«a lyric would be stored as [112118 = E “lyric OOOoooo”]»* y *«Lyrics events according to the Clone Hero spec need to start with a “phrase_start” event.»*:
  ```
  480 = E "phrase_start"
  480 = E "lyric hola"
  768 = E "lyric chao"
  960 = E "phrase_end"
  ```
- Marcadores tipo `lyric` y eventos: una **palabra/sílaba** por evento (el valor puede contener espacios, pero la solución del plan es una palabra por evento para poder borrar/sincronizar).
- Nota (S1): *«Any quote characters within the event phrase will result in the event loading incorrectly»* → **se prohíben** comillas y backslashes en el texto de letra (sanitize: Task 9 es responsable; parser se limita a des-quotear).

### Pistas de instrumento (S1 §Tracks; S3)
Nombre de la sección = dificultad + instrumento concatenados. Dificultades *Easy Medium Hard Expert*; instrumentos *Single DoubleGuitar DoubleBass DoubleRhythm Drums Keyboard GHL*. Ejemplos de S1: **`[ExpertSingle]`, `[MediumDrums]`**.

| Nuestro instrumento | Instrumento .chart | Secciones usadas |
|---|---|---|
| guitarra | Single | [Easy Single] → … [ExpertSingle] |
| bajo | DoubleBass | [ExpertDoubleBass] |
| bateria | Drums | [ExpertDrums] |

### N - Notas (S1 §N; S2 `s_noteFormat = " = N {0} {1}"`)
> «Notes are indicated by the “N” key and have 2 values. The first value is generally the fret number. The second value is the length, or “sustain” of the note in ticks.»

Línea exacta (S2): `<tick> = N <fret> <sustain>` — sustain SIEMPRE presente (flags con `0`). Round-trip: sustains en REMS conservan duración (S2 escribe `note.length * resolutionScaleRatio`).

Guitarra/Bajo (S1 §Guitar):
| fret | significado |
|---|---|
| 0–4 | lane verdes a naranja (1º a 5º fret) |
| 5 | flag “forced” (HOPO flip, 0 de sustain) |
| 6 | flag “tap” (0 de sustain) |
| 7 | open (con sustain) |

- HOPO: el juego activa HOPO automático si la separación < `(65/192)*resolution` ticks (S4 «Note Mechanics»: *"In .chart, the default threshold is `(65/192) * <chart resolution>` ticks"* → con res 192: 65 ticks); flags 5/6 anulan al contrario.
- Sustains encadenados: *«Chords may have individual notes with different lengths»* (S4); en .chart cada nota de un acorde lleva su duración propia.

Batería (S1 §Drums):
| fret | significado |
|---|---|
| 0 | kick (botón bombo) |
| 1–4 | lanes 1–4 (roja/amarilla/azul/verde) |
| 5 | lane 5 (solo batería de 5 lanes — NO la usamos) |
| 32 | double kick (Expert+) |
| 34–37 | acentos por lane (1–4) |
| 40–43 | ghosts por lane (1–4) |
| 66–68 | toggles pro de cymbal (NO: default toms) |

Star Power: `S 2 <longitud>` (S1 §S 2). Drum fill sobredrive: `S 64` (S1 §S 64); rolls `S 65/66` (no los usamos).
